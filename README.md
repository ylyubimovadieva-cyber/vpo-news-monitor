# Моніторинг новин про ВПО для «Конгрес ВПО України»

Сервіс кілька разів на день збирає новини з перевірених джерел про внутрішнє переміщення в Україні. Він залишає лише підтверджені, розносить їх за п'ятьма стовпами платформи «Національний конгрес стійкості» і готує короткий допис українською. Кожен допис надходить координаторці в Telegram на погодження.

**Жоден допис не публікується без натискання кнопки координаторкою.** Бойові канали вмикаються лише двома окремими налаштуваннями разом (див. розділ «Запуск у бойовому режимі»). Доти все працює в тестовому режимі.

## Як це працює

```
Джерела (RSS / сторінки новин)
   │  кожні 3 години; robots.txt, паузи між запитами, лише білий список
   ▼
Відбір за ключовими словами про ВПО  ──►  решта відкидається
   ▼
Групування новин про ту саму подію + перевірка «підтверджена»:
   першоджерело  АБО  два медіа різних власників
   │  не підтверджено за 72 години  ──►  у ранковий звіт «непідтверджені»
   ▼
Claude (claude-sonnet-5-5): релевантність, стовп, текст допису
   │  впевненість < 0,7, чутки, порушення правил тексту ──► звіт «сумнівні»
   ▼
Чернетка координаторці в Telegram: кнопки
   │  без відповіді 48 годин ──► прострочено, не публікується
   ▼
Публікація в тему групи (і на Facebook, якщо обрано), з денними лімітами
```

Правило «підтверджена новина» перевіряє **код**, а не модель. Модель лише підтверджує, що різні матеріали описують ту саму подію. Якщо модель вважає новину неперевіреною, чуткою чи сумнівною, новина не йде на погодження.

## Чому GitHub Actions

Сервіс працює в GitHub Actions за розкладом, без власного сервера:

- не потрібно орендувати, оновлювати й захищати сервер;
- секрети зберігаються в GitHub Secrets, координаторка вносить їх сама через вебінтерфейс;
- журнали кожного запуску видно у вкладці Actions.

Один процес `monitor` запускається кожні 10 хвилин. Щоразу він обробляє кнопки і публікує погоджене, раз на 3 години збирає новини, а о 9:00 за Києвом надсилає підсумок. Один процес замість кількох потрібен, щоб запуски ніколи не працювали з базою одночасно.

Насправді GitHub запускає розклад нерегулярно, буває раз на годину й рідше. Тому після своєї роботи процес ще слухає бота, разом до 45 хвилин: натискання кнопок і виправлені тексти обробляються за кілька секунд, а погоджений допис публікується одразу (з урахуванням лімітів). Наступний запуск стає в чергу і підхоплює прослуховування.

Стан (новини, чернетки, статуси) зберігається у файлі SQLite в окремій гілці `state` репозиторію. Ця гілка щоразу перезаписується, тож історія не розростається.

**Хвилини Actions.** Запуск кожні 10 хвилин – це приблизно 5 000 хвилин на місяць. У безкоштовному приватному репозиторії є лише 2 000 хвилин, а в публічному хвилини не обмежені. Тому радимо **публічний репозиторій із зашифрованою базою**: задайте секрет `STATE_KEY`, і вміст гілки `state` ніхто не прочитає. У коді й `config.yaml` немає секретів. chat_id координаторки в публічному репозиторії задавайте секретом `TELEGRAM_COORDINATOR_CHAT_ID`, а не в `config.yaml`. Якщо репозиторій має бути приватним, збільште інтервал у `.github/workflows/run.yml` (наприклад, `*/30`) і врахуйте, що погодження тоді спрацьовуватиме із затримкою до 30 хвилин.

Затримка між натисканням кнопки і публікацією становить до 10–15 хвилин: GitHub запускає розклад не секунда в секунду.

## Встановлення

1. Створіть репозиторій на GitHub (див. вище, публічний чи приватний) і завантажте туди вміст цієї теки.
2. У репозиторії відкрийте **Settings → Actions → General → Workflow permissions** і оберіть **Read and write permissions**. Це потрібно, щоб процес зберігав базу в гілку `state`.
3. Внесіть секрети (розділ нижче).
4. Заповніть `config.yaml`: `telegram.group_chat_id`, `telegram.topics` і `facebook.page_id`.
5. Запустіть тестовий прогін (розділ «Тестовий прогін») і оцініть стиль.
6. Увімкніть розклад: вкладка **Actions → monitor → Enable workflow**. До переходу в бойовий режим публікації йтимуть лише в тестову групу або в лог.

## Секрети: де взяти кожен

У GitHub: **Settings → Secrets and variables → Actions → New repository secret**. Ніде більше токени не зберігаються: ні в коді, ні в `config.yaml`, ні в журналах.

| Секрет | Обов'язковий | Що це і де взяти |
|---|---|---|
| `ANTHROPIC_API_KEY` | так | Ключ Claude API: [platform.claude.com](https://platform.claude.com) → Settings → API keys → Create key. Поповніть баланс у Billing. |
| `TELEGRAM_APPROVAL_BOT_TOKEN` | так | Токен бота погодження. У Telegram відкрийте @BotFather, надішліть `/newbot`, дайте назву, і BotFather поверне токен. |
| `TELEGRAM_PUBLISH_BOT_TOKEN` | ні | Окремий бот для публікації в групі. Якщо не задано, публікує бот погодження (тоді саме його треба зробити адміністратором групи). |
| `TELEGRAM_COORDINATOR_CHAT_ID` | так* | chat_id координаторки (див. нижче). *Або вкажіть у `config.yaml`, якщо репозиторій приватний. |
| `TELEGRAM_TEST_GROUP_CHAT_ID` | ні | chat_id тестової групи. Не секрет: зазвичай він уже вписаний у `config.yaml` (`telegram.test_group_chat_id`), змінна лише перекриває його. Якщо тестову групу задано, у тестовому режимі дописи з позначкою «[ТЕСТ]» ідуть туди; якщо ні – лише в журнал. |
| `FACEBOOK_PAGE_TOKEN` | ні | Довгостроковий токен сторінки Facebook (див. розділ про Facebook). |
| `LINKEDIN_ACCESS_TOKEN` | ні | Токен LinkedIn з дозволом `w_organization_social` для публікації на сторінці Конгресу (див. розділ про LinkedIn). Діє 60 днів. |
| `STATE_KEY` | радимо | Будь-який довгий випадковий пароль для шифрування бази. Збережіть його також у надійному місці: без нього стару базу не відкрити. |

Змінні режиму задаються не як секрети, а у вкладці **Variables** того самого розділу: `DRY_RUN` і `LIVE_CONFIRMED` (див. «Запуск у бойовому режимі»).

### chat_id координаторки

1. Координаторка відкриває бота погодження в Telegram, натискає **Start** і надсилає будь-яке слово.
2. Упродовж доби запустіть скрипт із токеном **бота погодження** (процес `monitor` у цей час має бути вимкнений):

```powershell
$env:TELEGRAM_APPROVAL_BOT_TOKEN = Read-Host "Токен бота погодження"
```

```powershell
.\.venv\Scripts\python scripts\get_topic_ids.py
```

3. Скрипт виведе рядок «Приватний чат з ботом: … – chat_id …». Це число вноситься в секрет `TELEGRAM_COORDINATOR_CHAT_ID`.

Бот погодження відповідає лише цьому chat_id. Натискання і повідомлення від будь-кого іншого ігноруються.

## ID групи і тем

Група «Національна платформа» (@idpcongressua) має бути з темами (forum topics): ДІМ, ГОЛОС, ТУРБОТА, ПОВЕРНЕННЯ, ПАМ'ЯТЬ.

1. Додайте бота-публікатора в групу і зробіть адміністратором із правом **надсилати повідомлення** (для тем – «Manage topics» не потрібне, достатньо права писати).
2. Якщо публікує той самий бот, що й погоджує, тимчасово вимкніть процес `monitor` в Actions, щоб він не «забрав» повідомлення.
3. Напишіть по одному короткому повідомленню в кожну з п'яти тем.
4. Запустіть скрипт (потрібен токен бота у змінній оточення):

```powershell
$env:TELEGRAM_PUBLISH_BOT_TOKEN = Read-Host "Токен бота"
```

```powershell
.\.venv\Scripts\python scripts\get_topic_ids.py
```

5. Скрипт виведе `group_chat_id` (від'ємне число на кшталт -100…) і `message_thread_id` кожної теми, а якщо назви тем видно – готовий фрагмент для `config.yaml`. Перенесіть числа в `telegram.group_chat_id` і `telegram.topics`.
6. Видаліть тестові повідомлення з тем і знову увімкніть процес.

Telegram зберігає ці повідомлення для бота 24 години, тож запускайте скрипт одразу після кроку 3. Для тестової групи так само можна заповнити `telegram.test_topics`.

## Facebook

Публікація йде на сторінку «Конгрес ВПО України» через Graph API (`/{page-id}/feed`) з посиланням на першоджерело. На Facebook потрапляє **лише** те, що координаторка погодила кнопкою «Опублікувати в Telegram і Facebook».

### Як отримати токен сторінки

Робить людина з роллю адміністратора сторінки:

1. Зайдіть на [developers.facebook.com](https://developers.facebook.com), **My Apps → Create App**, тип **Business** (або «Other → Business»). Назвіть, наприклад, «Конгрес ВПО – публікація».
2. Відкрийте **Graph API Explorer** ([developers.facebook.com/tools/explorer](https://developers.facebook.com/tools/explorer)), угорі оберіть свій застосунок.
3. **Add a Permission**: `pages_manage_posts`, `pages_read_engagement`, `pages_show_list`. Натисніть **Generate Access Token** і підтвердьте доступ до сторінки «Конгрес ВПО України». Це короткий токен користувача (діє близько години).
4. Обміняйте його на довгостроковий токен користувача: **Access Token Debugger** ([developers.facebook.com/tools/debug/accesstoken](https://developers.facebook.com/tools/debug/accesstoken)) → вставте токен → **Extend Access Token** (діє близько 60 днів).
5. Знову в Graph API Explorer, з довгостроковим токеном користувача, виконайте запит `GET me/accounts`. У відповіді знайдіть сторінку «Конгрес ВПО України»: поле `id` – це `facebook.page_id` для `config.yaml`, поле `access_token` – це **токен сторінки**.
6. Токен сторінки, отриманий із довгострокового токена користувача, зазвичай не має терміну дії. Перевірте це в Access Token Debugger (рядок «Expires: Never») і внесіть токен у секрет `FACEBOOK_PAGE_TOKEN`.

Поки застосунок у режимі розробки (Development), публікувати можуть лише люди з роллю в застосунку і на сторінці. Для публікації на власну сторінку цього досить, перевірка застосунку (App Review) не потрібна.

### Коли і як оновлювати токен

Токен сторінки перестає діяти, якщо людина, яка його створила, змінила пароль, втратила роль адміністратора сторінки, видалила застосунок чи доступ до нього, або якщо Meta скинула сесії. Тоді бот напише координаторці: «токен сторінки недійсний». Повторіть кроки 3–6 і замініть секрет `FACEBOOK_PAGE_TOKEN`. Допис, що не вийшов на Facebook, у Telegram усе одно публікується.

У `config.yaml` указано версію Graph API (`facebook.graph_api_version`). Meta підтримує кожну версію приблизно два роки; коли вона застаріє, змініть номер на актуальний.

### Як вимкнути Facebook

У `config.yaml` вкажіть `facebook.enabled: false`. Кнопка «Опублікувати в Telegram і Facebook» зникне з нових чернеток, і на Facebook нічого не публікуватиметься, навіть те, що вже стоїть у черзі.

## LinkedIn

Публікація йде на сторінку організації «Конгрес ВПО України» в LinkedIn через Posts API (`/rest/posts`). Посилання на першоджерело додається в кінець тексту. У LinkedIn потрапляє **лише** те, що координаторка погодила кнопкою «Опублікувати в Telegram, Facebook і LinkedIn». Ліміт – `linkedin.daily_limit` (2 на день). У тестовому режимі в LinkedIn нічого не йде, лише запис у журнал.

### Як отримати токен

Робить людина з роллю адміністратора (Super admin або Content admin) сторінки організації в LinkedIn:

1. На [linkedin.com/developers/apps](https://www.linkedin.com/developers/apps) → **Create app**. Назва, наприклад, «Конгрес ВПО – публікація»; у полі **LinkedIn Page** оберіть сторінку Конгресу; додайте логотип. Потім сторінка має підтвердити зв'язок із застосунком (**Verify** у вкладці Settings застосунку).
2. Вкладка **Products** → **Community Management API** → **Request access**. LinkedIn розглядає заявку і може попросити дані про організацію; без цього продукту дозволу на публікацію від імені сторінки немає.
3. Після схвалення: вкладка **Auth** → **OAuth 2.0 tools** → **Create token**, позначте дозвіл `w_organization_social` і підтвердьте вхід. Токен діє 60 днів.
4. Внесіть токен у секрет `LINKEDIN_ACCESS_TOKEN`.
5. ID організації – число з адреси адмінпанелі сторінки: `linkedin.com/company/<ID>/admin/`. Впишіть його в `linkedin.organization_id` у `config.yaml` (це не секрет).

Коли токен прострочиться, бот напише координаторці. Повторіть крок 3 і замініть секрет. Допис, що не вийшов у LinkedIn, у Telegram і на Facebook усе одно публікується.

Вимкнути LinkedIn: `linkedin.enabled: false` у `config.yaml` – третя кнопка зникне.

## Читання офіційних сторінок Facebook

Багато установ (ОВА, Укрдержархів, Офіс Омбудсмана, депутати, громадські організації) публікують новини для ВПО передусім у Facebook. Сервіс уміє читати їхні **сторінки** через офіційний Graph API (джерела `type: facebook` у `config.yaml`). Парсити facebook.com напряму не можна: robots.txt Facebook забороняє автоматичний збір без письмового дозволу Meta.

**Що потрібно від Meta.** Щоб читати дописи чужих сторінок, застосунок Meta має отримати функцію **Page Public Content Access**:

1. Пройти **Business Verification** організації в Meta Business Manager (документи про реєстрацію ГО).
2. У застосунку (можна той самий, що для публікації) подати **App Review** на Page Public Content Access: описати, що застосунок читає публічні дописи офіційних сторінок органів влади й організацій для моніторингу новин про ВПО, і додати відеозапис роботи. За словами сторонніх посібників, розгляд триває від кількох тижнів (офіційно не підтверджено).
3. Після схвалення створити **системного користувача** в Business Manager і згенерувати його токен. Внести токен у секрет `FACEBOOK_READ_TOKEN`.

Поки токена немає, джерела Facebook просто пропускаються: у журналі буде одне попередження, решта працює як завжди. Обмеження:

- Graph API читає лише **сторінки**, а не особисті профілі. Якщо адреса веде на профіль (наприклад, `facebook.com/pavlo.frolov.5`), у журналі з'явиться помилка, і таке джерело варто вимкнути (`enabled: false`).
- Якщо допис у Facebook посилається на новину на сайті установи з білого списку, у допис платформи піде посилання на сайт як на першоджерело.
- Допис офіційної сторінки вважається першоджерелом (`kind: primary`). Заяви й обіцянки без ухвалених рішень модель за інструкцією відкидає.

Як додати сторінку: `- {name: "Назва (Facebook)", type: facebook, page: "ім'я-сторінки-з-адреси", kind: primary}`. Ім'я – це частина адреси після `facebook.com/`.

## Офіційні іменні Telegram-канали

Telegram загалом заблоковано як джерело: анонімні канали заборонені. Виняток – офіційні іменні канали посадовців і установ зі списку `telegram_channels` у `config.yaml`. Зараз у списку:

- Дмитро Лубінець, Уповноважений ВРУ з прав людини – t.me/dmytro_lubinetzs;
- Павло Фролов, голова ТСК з питань захисту прав ВПО – t.me/frolovproparliament;
- УВКБ ООН в Україні – t.me/unhcr_ukraine_official (першоджерело);
- Суспільне Новини – t.me/suspilnenews і Українська правда – t.me/ukrpravda_news (верифіковані офіційні канали медіа, `kind: media`). Сайт Суспільного забороняє автоматичне читання, тому Суспільне береться з каналу. Канал і сайт одного видання мають однаковий `owner`, тож вони рахуються як одне медіа, а не два незалежні.

Радіо Свобода вимкнено.

Сервіс читає публічну вебсторінку каналу (`t.me/s/<канал>`), токен не потрібен. Допис каналу посадовця чи установи вважається першоджерелом, допис каналу медіа – повідомленням цього медіа. Якщо допис посилається на новину на сайті з білого списку (наприклад, ombudsman.gov.ua), у допис платформи піде посилання на сайт. Канал поза списком не читається взагалі, навіть якщо його додати в `sources`.

Як додати канал:

1. Переконайтеся, що канал офіційний: на нього посилається сайт установи або офіційна сторінка людини.
2. Додайте його в `telegram_channels`: `- {channel: ім'я_каналу, name: "Хто це", owner: ім'я_власника, kind: primary}`.
3. Додайте джерело в `sources`: `- {name: "Назва (Telegram)", type: telegram, channel: ім'я_каналу}`.

## Джерела і білий список

Усе редагується в `config.yaml`, код змінювати не треба.

- `whitelist.primary_domains` – першоджерела: органи влади (усі сайти `gov.ua`, зокрема Кабмін, Рада, міністерства, ПФУ, Омбудсман, ОВА), міжнародні організації, партнери. Субдомени враховуються автоматично.
- `whitelist.media` – медіа з полем `owner`. Два медіа з однаковим `owner` (наприклад, «Українська правда» і «Європейська правда») не вважаються незалежними.
- `blocked_domains` – заборонені домени (`.ru`, `.by`, Telegram, агрегатори) відкидаються завжди.
- `blocked_attribution_patterns` – якщо новина посилається на такі джерела (ТАСС, РИА та подібні), її відкинуто.
- `sources` – звідки збирати новини.

### Як додати джерело

1. Додайте домен у білий список: у `primary_domains` (органи влади, міжнародні організації, партнери) або в `media` з полем `owner`.
2. Додайте запис у `sources`:
   - для RSS: `- {name: "Назва", type: rss, url: "https://сайт/rss"}`;
   - для сайту без RSS: `- {name: "Назва", type: html, url: "https://сайт/news", link_regex: "/news/[a-z0-9-]+"}`, де `link_regex` описує адреси окремих новин на сторінці списку.
3. Перевірте:

```powershell
.\.venv\Scripts\python -m vpo_news check-sources
```

Щоб тимчасово вимкнути джерело, допишіть до запису `enabled: false`.

## Рубрика «МОЖЛИВОСТІ»: гранти і програми для ВПО

Крім п'яти стовпів, є рубрика **«МОЖЛИВОСТІ – гранти і програми для ВПО»** з власною темою в групі. Тему треба створити в групі «Національна платформа» і записати її ID у `telegram.topics.MOZHLYVOSTI` (скрипт `get_topic_ids.py` її розпізнає).

- Сюди йдуть гранти, конкурси, стипендії, навчальні програми й інші можливості, на які ВПО або організації, що з ними працюють, можуть подати заявку. Тематичний стовп (наприклад, ДІМ для житлового гранту) зберігається як другий.
- Допис обов'язково містить: хто може подати заявку, що можна отримати, дедлайн і як подати.
- Без чіткого дедлайну в першоджерелі або якщо до дедлайну лишилося менше 2 днів, допис потрапляє в «сумнівні» і не йде на погодження.
- Якщо дедлайн минув, поки погоджений допис чекав у черзі через ліміти, він не публікується, а координаторка отримує повідомлення.
- Діють ті самі правила підтвердження: оголошення має бути на сайті чи офіційній сторінці донора або організації.

## Правила тексту

Автоматично перевіряються:

- перший рядок – назва стовпа дослівно (наприклад, «ДІМ – право на стабільність»);
- довжина всього допису від 400 до 700 символів (разом із назвою стовпа і посиланням);
- є посилання саме на першоджерело;
- немає хештегів, емодзі, довгих тире «—» і знаків оклику (довгі тире і знаки оклику автоматично замінюються);
- немає оцінних слів («нарешті», «ганебно» тощо), якщо їх немає в першоджерелі;
- немає тверджень, що Конгрес чи платформа «виконує» або «впроваджує» Стратегію.

Канцеляризми, повтори, телефони й e-mail не блокують допис, а показуються координаторці як попередження. Імена приватних осіб модель не згадує за інструкцією, але остаточно це перевіряє координаторка.

## Погодження в Telegram

Кожна чернетка надходить окремим повідомленням: стовп, текст, посилання на джерело, підстава підтвердження, впевненість моделі, строк погодження і кнопки:

- **Опублікувати в Telegram** – у тему основного стовпа;
- **Опублікувати в Telegram і Facebook**;
- **Опублікувати в Telegram, Facebook і LinkedIn** (є, поки `linkedin.enabled: true`);
- **Редагувати** – бот попросить надіслати виправлений текст. Назву стовпа і посилання можна не писати, бот додасть їх сам. Текст перевіряється за тими самими правилами. Бот надсилає нову версію з кнопками, і публікується саме вона, після повторного натискання;
- **Відхилити**.

Чернетки без відповіді впродовж 48 годин позначаються як прострочені й не публікуються. Щодня о 9:00 за Києвом бот надсилає підсумок: скільки знайдено, скільки чекає рішення, що опубліковано, що відхилено як непідтверджене і що потрапило в «сумнівні».

Ліміти: не більше 3 дописів на тему на день у Telegram і не більше 2 дописів на день у Facebook. Надлишок автоматично переходить на наступний день у порядку погодження.

## Тестовий прогін

Готує 5 чернеток, по одній на кожен стовп, щоб оцінити стиль. Нічого не публікує. Спершу береться реальна підтверджена новина за останні 72 години. Якщо для стовпа такої немає, береться синтетичний приклад із тестів, і це чітко позначено у звіті.

```powershell
$env:ANTHROPIC_API_KEY = Read-Host "Ключ Anthropic"
```

```powershell
.\.venv\Scripts\python -m vpo_news samples
```

Результат буде у файлі `samples/dry_run_samples.md`. З прапорцем `--send` зразки (без кнопок, з позначкою «ЗРАЗОК») також надійдуть координаторці в Telegram. Прогін триває кілька хвилин через паузи між запитами до сайтів і коштує орієнтовно 10–30 центів.

## Тести

```powershell
.\.venv\Scripts\python -m pytest -q
```

- правила тексту: хештеги, емодзі, довгі тире, знаки оклику, посилання, довжина, оцінні слова, твердження про Стратегію;
- білий і чорний списки, правило «першоджерело або два незалежні медіа», дублікати;
- класифікація на 20 синтетичних прикладах (`tests/fixtures/news_examples.json`): попередній відбір, ключові слова стовпів, увесь конвеєр, стара новина, чутка з одного медіа, російський домен, Telegram-канал;
- погодження: кнопки, сторонні користувачі, редагування, прострочення, ліміти, DRY_RUN.

Живий тест моделі на тих самих прикладах (коштує кілька центів):

```powershell
$env:RUN_LIVE_TESTS = "1"; .\.venv\Scripts\python -m pytest -q tests\test_classification.py
```

## Запуск у бойовому режимі

За замовчуванням `DRY_RUN=true`: усе працює, але публікації йдуть у тестову групу або лише в журнал. Бойові канали вмикаються лише коли **обидві** змінні мають такі значення:

- `DRY_RUN` = `false`
- `LIVE_CONFIRMED` = `true`

Обидві задаються в **Settings → Secrets and variables → Actions → Variables**. Задавайте їх лише після того, як координаторка оцінила зразки і явно підтвердила запуск. Щоб повернутися в тестовий режим, змініть `DRY_RUN` на `true`.

## Вартість

- GitHub Actions: див. розділ «Хвилини Actions».
- Claude API (claude-sonnet-5-5): модель викликається лише для підтверджених новин про ВПО, зазвичай 10–40 разів на день, по 1–3 центи за виклик. Разом приблизно 5–30 доларів на місяць.

## Журнали і приватність

У журналах лише службові дані: кількість, домени, номери чернеток. Тексти дописів, токени й персональні дані туди не пишуться; токени додатково маскуються. База містить лише новини з відкритих джерел і статуси чернеток.
